# Contributing

1. Describe a reproducible issue or proposed model change in an issue.
2. Create a branch and keep the change focused.
3. Add a meaningful test for solver, import or export behavior.
4. Run `npm test` and `npm run build`.
5. Include the expected behavior, verification and limits in your pull request.

Do not commit secrets or beneficiary records. Changes to fairness objectives need an explanation of who benefits and who is disadvantaged. Keep synthetic examples labeled. Respect the MIT license and third-party dependency licenses.
